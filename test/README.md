# NFTest fixtures

From the repository root, copy `.env-template` to `.env` and set `DATA_DIR` to the fixture root. Every test case uses an mzML or consensusXML CSV plus an idXML CSV; mzML cases also use a channel CSV keyed by plex ID. `csv_environment_expander.groovy` expands `DATA_DIR` and `NFT_PIPELINE` in the source and idXML CSVs before Nextflow reads them. Run `test/run-nftest.sh <case-name>` inside a Slurm job from the repository root. The wrapper sets `NFT_OUTPUT` and sources the repository-root `.env`. For local runs, export the same variables and run `nftest run -c nftest.yml <case-name>`.

`test-integration-MAD-PhysicalReference` uses two plex IDs with three mzML paths and one validated idXML per plex, plus 10 reporter-channel rows per plex from the D’Angelo E. coli TMT subset. It uses reporter channel 126 as the physical reference, leaves the isotope-correction matrix at the OpenMS default, and selects MSPtools MAD normalization with the default 1.1.1 image. It retains NaN reporter handles and writes quasi-intensities, as the pipeline does by default. An earlier single-plex cluster run using the `dev` image passed with all 888 peptide CSV rows aligned to the 10 channel headers.

`test-integration-VirtualReference` uses the same two-plex mzML and idXML fixtures, but configures MAD normalization with a median virtual reference and treats all ten reporter channels as channels in that calculation. It leaves isotope correction at the OpenMS default, retains NaN handles, and writes quasi-intensities. An earlier cluster run using the `dev` image passed with 888 peptide CSV rows aligned to the 10 channel headers. `csv_environment_expander.groovy` expands environment variables to absolute paths before Nextflow reads each CSV. Full integration requires the fixture files and configured containers on the cluster.

`test-integration-mergedConsensusXML` starts from two existing consensusXML files whose column headers already contain channel descriptions. Its consensusXML CSV has one row per plex and no channel CSV. This case also exercises the optional unmapped-feature output; an earlier single-plex implementation passed on the cluster.

The existing cluster passes predate the multi-plex CSV change. All three cases need to be rerun with the dataset-level scan workflow and MSPtools 1.1.1 image.

`test-integration-FeatureBasedTMT` uses two D’Angelo plexes, each with three mzML source files paired by `fraction_id` (`F1`–`F3`). It exercises idXML splitting, FFId detection, reporter matching, cross-plex feature linking, MS1-scale channel area output, and one dataset consensusXML, MAD-normalized consensusXML, peptide CSV, scaling report, and linked-feature TSV across plexes and fractions. The linked table retains raw estimated areas and adds normalized areas and plex factors; the test enables bridge scaling with a median virtual reference and a one-channel minimum. Channel 126 is labeled as a sample and participates in the virtual reference. The scaling factor uses all positive finite virtual-reference areas per plex, rather than requiring shared features. The fixture is a technical smoke test, not evidence of cross-plex accuracy. Under OpenMS 3.6, check that every detailed peptide CSV row has the header's width, including zero-filled cells for absent plexes, before and after MSPtools cleanup. Compare charge, fraction, and abundance columns with the resolved consensusXML. Rerun NFTest on the cluster to verify the updated workflow end to end.

All four integration cases now use OpenMS 3.6 for TOPP commands while retaining the upstream OpenMS 3.5 mzML, idXML, and consensusXML fixtures. The scan-based cases cover two plexes and three source files per plex; the feature-based case additionally carries three input `fraction_id` values per plex. The pipeline's current fraction merge reuses one set of plex/channel headers across fractions, so ProteinQuantifier sees one design fraction per plex in the dataset CSV. The linked-feature TSV retains the input fraction IDs. Check the separate fraction representation before interpreting a peptide CSV fraction label as a source-file fraction.

After an NFTest run, inspect the pre-cleanup ProteinQuantifier CSV under `intermediate/<dataset_id>/quantify_peptides/` and the final `fixZeroPlex` CSV. Confirm that every row has one value per abundance header, that the headers follow the resolved consensusXML map order, and that absent plexes have zero-filled columns before cleanup and missing values afterward. Compare charge and fraction labels with the intended output. OpenMS 3.6's own fractionated two-file fixture demonstrates full-width rows; the D’Angelo cases still require cluster validation.
